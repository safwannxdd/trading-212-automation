# Deploying the T212 momentum bot to Google Cloud

Generated by Section 11 of `1st_Paper_Trial.ipynb`. Regenerate after any notebook change:

    export_bot_script(); write_deployment_files()

## Before anything else

1. `preflight_checks(client)` must pass in the notebook.
2. Keep `DRY_RUN = True` for at least one full week of cycles and read `t212_bot.log`.
   Confirm the response field names (`fillPrice`, `ticker`, `quantity`, `freeFunds`, `stopPrice`)
   against a real payload before flipping it off.
3. `ENVIRONMENT` stays `"demo"` until the demo soak looks correct.

## 1. Create the instance

Machine type `e2-micro`, Ubuntu 22.04 LTS, 30GB standard persistent disk, in **us-west1,
us-central1 or us-east1** -- the only always-free regions. Latency is irrelevant here.

Set a **budget alert at 1 GBP** under Billing first. The free tier needs a billing account
attached, and the alert is how you learn immediately if anything drifts outside it.

The bot needs ~250MB of RAM and almost no CPU. What matters is that it keeps running, and GCP's
always-free e2-micro is not reclaimed for sitting idle.

## 2. Copy the bot across

From your laptop, in the folder that contains `deploy/`:

    gcloud compute scp --recurse deploy/ INSTANCE:~/t212-bot --zone=ZONE

No git repo needed. To update later, re-run this then restart the service (see below).

## 3. Add your credentials on the VM

    gcloud compute ssh INSTANCE --zone=ZONE

    cat > ~/t212-bot/.env <<'ENVEOF'
    T212_API_KEY=your_demo_key
    T212_API_SECRET=your_demo_secret
    ENVEOF
    chmod 600 ~/t212-bot/.env

Create it here rather than copying your local `.env` up -- the keys then only ever exist in two
places you control. `install.sh` never touches them.

## 4. Install and start

    cd ~/t212-bot && ./install.sh

The script works out the Linux username and paths itself, sets up swap and UTC, builds the
virtualenv, writes the systemd unit and starts the service. `Restart=always` brings the bot back
after a crash or a VM reboot.

## 5. Verify

    systemctl status t212-bot
    tail -f ~/t212-bot/t212_bot.log

A healthy DRY_RUN cycle logs `=== Cycle start [DRY RUN] ===`, a `Target portfolio:` line on
rebalance days, `Stop coverage: n/n positions have a resting stop`, and `=== Cycle end ===`.

## Operating notes

- **Updating:** re-run the scp from step 2, then `sudo systemctl restart t212-bot`.
- **Reading the soak report:** pull the log back with
  `gcloud compute scp INSTANCE:~/t212-bot/t212_bot.log . --zone=ZONE`, then run `soak_report()`
  in the notebook against it.
- Free egress is 1GB/month; this bot uses a tiny fraction (yfinance data is inbound, the T212
  calls are a few KB each).
- `entry_prices.json` holds your stop-loss anchors and lives on the instance disk. If you rebuild
  the VM, `seed_missing_entry_prices()` re-anchors from the broker rather than leaving open
  positions unprotected.
